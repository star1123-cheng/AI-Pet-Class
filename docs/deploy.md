# GAS 部署步驟與權限說明

本文件不含任何金鑰。全部步驟用你自己的 Google 帳號操作，Claude Code 無法代做。

## 0. 先知道的事

- 遊戲網頁放在 GitHub Pages，是**公開的靜態網頁**：任何人都看得到網頁原始碼，所以它保護不了任何祕密。`config.js` 裡只放 GAS 網址，不放金鑰、密碼、token。
- 沒填 GAS 網址時（`config.js` 的 `GAS_URL` 是空字串），遊戲是「離線模式」，資料只存在 iPad，一樣能玩。

## 1. 建立試算表與程式

1. 用**你的帳號**建立一份新的 Google 試算表，命名例如「AI 寵物 班級資料」。
2. 試算表選單「擴充功能」→「Apps Script」。
3. 左邊「專案設定」（齒輪）→ 勾選「在編輯器中顯示『appsscript.json』資訊清單檔案」。
4. 回到「編輯器」，建立 3 個指令碼檔，把 repo 裡的內容整份貼上：
   - `Shared.gs`（序號與外型規則）
   - `Code.gs`（學生端 API）
   - `Admin.gs`（老師選單）
5. 打開 `appsscript.json`，整份換成 repo 裡 `gas/appsscript.json` 的內容。
6. 按儲存。

## 2. 授權與建立分頁

1. 編輯器上方選函式 `setupSheets` → 按「執行」。
2. 會跳出授權視窗，請確認**只列出這兩項**（實際文字以 Google 畫面為準）：
   - 查看及管理「這份試算表」（`spreadsheets.currentonly`：只能動這一份，碰不到你雲端硬碟的其他檔案）
   - 在試算表裡顯示選單與對話框（`script.container.ui`）
   - 如果出現「查看、編輯、建立及刪除您所有的 Google 雲端硬碟檔案」之類的權限，**先不要允許**，回報給 Claude Code。
3. 回到試算表重新整理，上方會出現「AI 寵物」選單。

## 3. 發序號

1. 「AI 寵物」→「2. 發 40 組序號」。序號會出現在 `serials` 分頁，外型保證不重複。
2. 「AI 寵物」→「3. 匯出序號卡（CSV）」→ 下載 `serials.csv`，用來印序號卡。
3. 「班級代號＋座號 ↔ 序號」對照表請**另外保存**，不要貼進這份試算表。

## 4. 部署成 Web App（請先讀完風險說明）

### 設定

「部署」→「新增部署作業」→ 類型選「網頁應用程式」：

| 欄位 | 設定 |
|------|------|
| 說明 | 例如「P2 第一版」 |
| 執行身分（Execute as） | **我（你的帳號）** |
| 誰可以存取（Who has access） | **所有人（Anyone）** |

按「部署」後複製「網頁應用程式網址」（結尾是 `/exec`），填進 `config.js`：

```js
export const GAS_URL = 'https://script.google.com/macros/s/……/exec';
```

### 為什麼要用這個組合？

| 組合 | 能不能用 | 原因 |
|------|----------|------|
| 我＋只有我自己 | ✗ | 學生打不開 |
| 我＋學校網域內的使用者 | ✗（推論） | 從 GitHub Pages 用 `fetch` 呼叫時，瀏覽器不會帶上學生的 Google 登入，請求會被擋下 |
| 存取者＋任何人 | ✗ | 每位學生都要授權，而且學生帳號沒有這份試算表的權限 |
| **我＋所有人** | ✓ | 唯一能從 GitHub Pages 呼叫的組合 |

### 風險

「執行身分：我」＋「所有人」代表：**任何拿到網址的人，都能用你的權限呼叫這支程式**。如果程式寫得太寬，就等於把你的帳號權限借給陌生人（這叫「權限升級」風險）。

### 這個專案怎麼降低風險

1. **權限只到這份試算表**：`appsscript.json` 只宣告 `spreadsheets.currentonly`，程式碰不到你的雲端硬碟、Gmail 或其他試算表。
2. **網址上沒有管理功能**：發序號、清空資料都只在試算表選單，`doPost` 只接受 `claimPet`、`getPet`、`savePet`、`logEvent`、`batch`。
3. **每次寫入都檢查**：序號要格式正確、檢查碼正確、而且在 `serials` 分頁裡；欄位只收數字與選項代碼，不收自由文字；請求最多 20,000 字元。
4. **外型由伺服器決定**：前端送來的外型一律不採用。
5. **不印出內容**：程式不用 Logger 或 console 記錄請求。

殘留風險：知道網址又知道有效序號的人，可以改那隻寵物的狀態數字。影響限於遊戲分數，不會外洩個資（試算表裡只有序號）。

### 學校帳號可能遇到的情況

- 如果「誰可以存取」沒有「所有人」可以選，代表學校 Google Workspace 管理員關掉了這個選項，需要詢問學校資訊窗口（這是 README 待辦裡「GAS 能被學生存取」那一項）。

## 5. 課前驗收（你來做）

1. **30 人同時存檔測試**（在專案資料夾執行）：

```bash
node tools/stress-30.mjs "你的 GAS 網址" serials.csv
```

   看到「結果：通過」就完成。測完到試算表選單按「清空測試資料…」。

2. **iPad 斷網領養**：
   - iPad Safari 開啟 GitHub Pages 上的遊戲 → 關掉 Wi-Fi → 輸入序號領養 → 看到「還有 N 筆資料，等網路恢復後會自動上傳」
   - 打開 Wi-Fi，等 20 秒左右 → 顯示「✓ 已存到雲端」→ 試算表 `pets` 多一列、`events` 多一筆 `adopt`

## 6. 更新程式（保留回退能力）

- 改完程式後：「部署」→「管理部署作業」→ 編輯（鉛筆）→ 版本選「新版本」→ 部署。**網址不變**，`config.js` 不用改。
- 出問題時：同一個畫面把版本切回上一版，就能回退。

## 7. 全班同時使用的限制（假設）

- Google 對同一個帳號「同時執行」的次數有上限（官方配額表寫的是 30，請以 Google 最新公告為準）。「執行身分：我」代表全班的請求都算在你帳號上。
- 遊戲的對策：寫入失敗會留在 iPad 的佇列，每 20 秒自動重送；畫面不會卡住。

## 8. 出事時怎麼辦

如果發現網址被班級以外的人亂用，或權限開得太大：

1. **止血**：「部署」→「管理部署作業」→ 封存這個部署（網址立刻失效）。
2. **評估影響**：查看試算表的「版本記錄」，看資料被改了什麼。
3. **重新部署**：新增一個部署作業，把新網址填進 `config.js`。
4. 依校園資安通報流程，評估是否需要通報。

## 9. 資料保存提醒

- 試算表存在 Google（國外服務），雖然只有序號，仍屬資料委外處理；必要時先向學校資安窗口報備。
- 保存期限與刪除時機請填進 `docs/05` 第 7 節。建議課程結束（第 6 堂後）匯出需要的統計，再刪除整份試算表。
