# 資料與教師看板規格

## 1. 架構

- 前端：GitHub Pages（純 HTML/CSS/JS）
- 後端：Google Apps Script Web App ＋ 單一試算表（一班）
- offline-first：GAS 失敗時遊戲照常運作，事件寫入 localStorage 佇列，連線後補送
- 前端用 `fetch` 以 `text/plain` 傳 JSON，避開 CORS 預檢
- 寫入使用 `LockService`，因為全班同時寫入
- 設定檔 `config.js` 只放 GAS URL；金鑰、密碼、token 不進 repo
- GAS 部署組合：Execute as「Me」＋ Who has access「Anyone」（從 GitHub Pages 呼叫只有這個組合可行）。風險與降低方式見 `docs/deploy.md`：權限只到這份試算表（`spreadsheets.currentonly`）、每次寫入都檢查序號已發出與欄位格式、學生端網址不提供任何管理功能
- 管理功能（發序號、匯出序號卡、清空測試資料）做成試算表的自訂選單「AI 寵物」，只有擁有者開啟試算表時能用，不開放網址
- 教師看板是**另一個** Apps Script 專案（`gas-dashboard/`），一樣綁在這份試算表上，部署成 Execute as「Me」＋ Who has access「Only myself」：別人打開網址會被 Google 擋下。學生端那支「Anyone」的網址完全沒有管理功能。兩個專案的 `Shared.gs` 必須一模一樣（測試會檢查）

## 2. 序號與外型

- 序號 6 碼，字元集 `ABCDEFGHJKMNPQRSTUVWXYZ23456789`（去掉 I、L、O、0、1，共 31 個字元）
- 第 6 碼是檢查碼：前 5 碼在字元集的位置為 v1…v5，檢查碼位置＝(1×v1＋2×v2＋3×v3＋4×v4＋5×v5) mod 31。打錯一個字或前後兩字對調，離線也能發現
- 學生輸入時自動轉大寫、去掉空白與「-」
- 發 40 組（30 人＋10 備用），發號時由 GAS 檢查外型參數組合唯一
- 外型參數由序號決定（序號經 FNV-1a 32 位元雜湊後 mod 34,560，再依下表順序拆成各參數），發號時保證每人不同：

| 參數（程式名稱） | 選項數 | 選項 |
|------|--------|------|
| 物種（body） | 6 | 貓、狗、兔、熊、狐狸、倉鼠 |
| 毛色（color） | 12 | 橘子、奶油、焦糖、可可、灰藍、炭灰、雪白、桃粉、薄荷、天藍、薰衣草、檸檬 |
| 眼睛（eyes） | 5 | 圓圓眼、亮晶晶、開心眼、像素眼、貓瞳眼 |
| 配件（accessory） | 6 | 無、蝴蝶結、耳機、智慧護目鏡、AI 天線、領巾 |
| 花紋（pattern） | 4 | 無、電路紋、條紋、額白＋肚白 |
| 耳型（ears） | 4 | 依物種不同，例如貓：立耳、折耳、簇毛耳、大耳；狗：立耳、垂耳、長垂耳、半折耳 |

組合數 34,560，遠大於班級人數；以 SVG／CSS 繪製（大頭 Q 版插畫風，每隻胸前都有一顆「AI 核心」，亮度跟著準確率變（見下方），尾巴會搖、眼睛會眨，「減少動態效果」開啟時不動），不使用外部圖片，也不使用現有動漫或遊戲角色。參數的拆解順序與選項數不可更動（GAS 端 `gas/Shared.gs` 用同一套規則檢查外型不重複），只能改「怎麼畫」。
- AI 核心亮度（只看 `state.accuracy`，不屬於外型參數，也不影響外型不重複）：

| 準確率 | 核心 |
|--------|------|
| 還沒考過（null） | 熄燈：灰色、不發光 |
| 未滿 40% | 微光 |
| 40%–69% | 亮 |
| 70% 以上（與第 2 堂解鎖「計分」的門檻一致） | 全亮：光暈變大、有小星光 |

- 老師端匯出「序號卡」CSV（只有序號），「班級代號＋座號 ↔ 序號」對照表由你另存，**不放進這份試算表**。

## 3. 試算表分頁

| 分頁 | 欄位 |
|------|------|
| pets | serial、appearance(JSON)、lesson、state(JSON)、skills(JSON)、badges(JSON)、updated |
| samples | serial、idx、label、g（原圖格，128 字元十六進位）、s（形狀格，128 字元十六進位，見第 5 節「辨識特徵」）、flagged、ts |
| events | ts、serial、lesson、type、code、value、eid（事件編號，補送重複時不重複寫入） |
| quiz | serial、form(A/B)、q、choice、ts |
| tasks | serial、taskId、status(self/confirmed)、ts |
| prompts_log | serial、lesson、blocks(JSON 積木 ID)、copyCount、ts |
| config | currentLesson、skillOverrides |
| serials | serial、claimed（無姓名） |
| energy_resets | serial（`*` 代表全班）、lesson、ts（毫秒）：老師在看板按「重設能量」 |

- tasks 的 status：`self` 學生自報、`confirmed` 老師在看板確認。自報任務代碼見 `docs/03` 第 3 節
- energy_resets 是 P7 新增的分頁；舊試算表沒有這個分頁時，學生端當成空的，看板第一次重設時自動建立

`state`：dataCount、dataQuality、trainCount、accuracy、classes。

- dataCount：沒被標成錯誤的範例張數
- trainCount：餵食次數（每按一次「餵給 AI」、每加入一次神祕資料包算 1 次）。k 近鄰沒有另外的訓練步驟，把範例加進記憶就是牠的訓練
- accuracy：目前堂次的內建測試集準確率（見 `docs/03` 5.2），還沒有範例時是 null
- samples 的 flagged：`FALSE` 正常、`TRUE` 學生確認標錯、`removed` 學生刪掉（保留列給老師看資料清理過程，getBrain 不回傳）
- 前端寵物存檔另有 `samples`（`{idx, label, g, s, flagged}`，只存在 iPad 與 samples 分頁）與 `play`（第 1、2 堂進度），savePet 不送這兩個欄位

## 4. API（POST，action 欄位決定）

學生端：`claimPet`、`getPet`、`savePet`、`saveSamples`、`logEvent`、`submitQuiz`、`reportTask`、`logPrompt`、`getBrain`（合併夥伴用，回傳外型、技能、腦袋）、`batch`（補送佇列，一次送多筆）
管理端（試算表選單，不開放網址）：`issueSerials`、匯出序號卡、清空測試資料
教師看板（`gas-dashboard/`，只有本人能開，頁面用 `google.script.run` 呼叫，不是 POST）：`getDashboard`、`getDisplay`、`confirmTask`、`resetEnergy`、`setLesson`、`issueSpareSerial`、`lookupSerial`，見第 6 節

P2 已實作：`claimPet`、`getPet`、`savePet`、`logEvent`、`batch`。P5 已實作：`logPrompt`、`getBrain`。P3 已實作：`saveSamples`、`submitQuiz`。P7 已實作：`reportTask`。

- 請求：`{"action": "...", ...欄位}`；回應：`{"ok": true, ...}` 或 `{"ok": false, "error": "代碼"}`
- `claimPet {serial}`：序號必須已發出；第一次領養會建立 pets 列並把 serials 的 claimed 設為 true；已領養過則回傳試算表上的寵物（換 iPad 時可接續）。回應含 `pet` 與 `currentLesson`
- `getPet {serial}`：回傳 `pet`（未領養為 null）、`currentLesson`、`energyReset`（這個序號或全班在目前堂次最近一次被重設能量的時間，毫秒，沒有就是 0；前端比這台 iPad 上次套用的新，就把這堂能量歸零）與 `tasks`（`[{taskId, status}]`）。前端在回到寵物畫面時呼叫（最多每 30 秒一次，從別的 App 切回來也會呼叫），iPad 記得序號的學生也能跟上老師切換的堂次；寵物的堂次一律以 `currentLesson` 為準
- `savePet {serial, lesson, state, skills, badges, updated}`：外型一律由伺服器依序號重算，不採用前端送來的值；`updated` 比試算表舊的不覆蓋
- `logEvent {eid, serial, lesson, type, code, value}`：`eid` 已存在就略過（回應 `dup: true`）
- `logPrompt {serial, lesson, blocks, copyCount}`：寫入 prompts_log；`blocks` 只收積木代碼（小寫字母＋1～2 位數字，例如 `w1`、`c4`，最多 30 個），有任何不符就整筆拒收；同一序號、同一堂、同一個 `copyCount` 已存在就略過（回應 `dup: true`），所以補送不會重複
- `getBrain {serial}`：合併夥伴用，只讀。回傳 `appearance`（依序號重算）、`skills`、`brain`（samples 中沒被標成錯誤的樣本 `{label, g, s}`，最多 200 張）；夥伴沒領養回傳 `not_claimed`
- `saveSamples {serial, samples: [{idx, label, g, s, flagged}]}`：一次最多 20 張；依 `serial＋idx` 新增或覆蓋（補送重複不會多出列）。`label` 只收 4 個類別、`g`／`s` 必須是 128 字十六進位、`idx` 為 0～9999 整數、`flagged` 為 true、false 或 `"removed"`；任一張不符整筆拒收。每個序號最多 300 列
- `submitQuiz {serial, form, answers: [{q, choice}]}`：`form` 為 A 或 B，`q` 為該版的 5 題代碼，`choice` 為 a／b／c；同一序號同一題已有紀錄就略過（只記第一次）
- `reportTask {serial, taskId}`：學生在 Canvas 做完任務、按「我完成了」。`taskId` 只收自報任務代碼（`l4s1`、`l4s2`、`l4s3`、`l5s1`、`l5s2`），寫入 tasks（status `self`）；同一序號同一任務已有紀錄就略過（回應 `dup: true`，已確認的不會被改回自報）
- `batch {items: [{eid, action, payload}]}`：最多 50 筆、內容合計不超過請求上限（前端依字數分批），逐筆回傳結果（可放 `claimPet`、`savePet`、`logEvent`、`logPrompt`、`saveSamples`、`submitQuiz`、`reportTask`）；前端收到成功或「永久錯誤」（例如序號不存在）就移出佇列，其餘下次再送
- 格式限制：`type`、`code` 為英數與 `_.-`，最多 32 字；`value` 為數字或同規則字串；技能只接受 `docs/04` 的 9 個 ID；請求內容最多 20,000 字元；不收自由文字
- 錯誤代碼：`bad_request`、`bad_serial`（格式或檢查碼錯）、`unknown_serial`（沒發過）、`not_claimed`、`busy`（等鎖逾時，前端稍後重送）

## 5. 資料品質指標

`dataQuality` 0–100，權重可調，公式寫在 `engine/health.js` 並同步本節：

- 類別平衡＝最少張數／最多張數（權重 0.4）
- 多樣性＝各類 bbox 面積標準差的標準化值（權重 0.3）
- 乾淨度＝1－已確認標錯張數／總張數（權重 0.3）

P1 實作細節（`engine/health.js`）：
- bbox 面積以 16×16 原圖格計算，灰階 ≥ 0.2 的格子算有畫到
- 多樣性：每類算面積變異係數（標準差÷平均），除以 0.35 後最多取 1，再取各類平均；少於 2 張的類別算 0
- 類別平衡：本堂應有的類別中，有任一類 0 張就是 0
- 沒有資料時 `dataQuality`＝0
- 可疑樣本：每類（至少 3 張）離同類中心最遠的那張；若它離別類中心更近，標示「可能是別類」

### 辨識特徵（P1 實驗結果，待確認）

每張圖存兩種 16×16 特徵：
- 原圖格 `g`：不縮放置中，保留大小與位置（第 2 堂偏誤實驗靠它）
- 形狀格 `s`：先把筆畫外框裁成正方形並放大，再轉 16×16

k 近鄰（k＝3）距離＝形狀格與「原圖格×0.8」合起來的歐氏距離。原因：只用原圖格時，合成混合測試集準確率約 53%，達不到 85%；只用形狀格則偏誤實驗消失（大圓、小圓準確率差距 0）。權重 0.8 時兩者都達標（數據見 P1 回報）。

## 6. 教師看板

程式：`gas-dashboard/Dashboard.gs`（彙整是純函式 `buildDashboard_`，`test/dashboard.test.js` 用 30 個模擬序號驗算）、`gas-dashboard/Dashboard.html`。

- 各題答對率（迷你任務單）：第 1～3 堂各 3 題，同一序號同一題只算第一次作答
- 全班資料量與資料品質分布（直方圖，只算已領養的）：資料量分 0、1–9、10–19、20–29、30–39、40 以上；資料品質分 0–19、20–39、40–59、60–79、80–100
- 技能解鎖進度（3×3 熱圖，列＝第 2～4 堂，欄＝★～★★★，格子是人數／已領養）
- 前後測整班差異（去識別化，只顯示題目層級）：A、B 版同題號為平行題，各題答對率與變化（百分點）；兩版平均答對題數，另列「兩次都做」的學生平均
- 班級合作指標：
  - 全班累積餵食張數＝`feed` 事件數（每餵一張記一筆）
  - 偵測偏誤次數＝大小圓偏誤實驗（`exp`）＋資料健檢標錯或刪掉（`clean`）＋神祕資料包找出的標錯張數（`pack` 的 value）
  - 修復成功次數＝第 3 堂修嘴巴過關（`fix`，溫度 ≤ 低、錯句 ≤ 1）＋第 2 堂修好 AI 後達成 `l2s1`、`l2s3`（`task` 事件，每人每任務一次）＋第 4 堂修好保底版 `l4s2`（老師確認後）
- 待確認清單：學生自報完成的任務（按序號、依自報時間排），一鍵確認。老師也可以直接確認學生還沒自報的任務（`confirmTask` 找不到列就新增一列 `confirmed`）
- 操作：
  - 切換目前堂次（寫 config 的 currentLesson，學生回到寵物畫面時跟著換，最多等 30 秒）
  - 重設能量：輸入序號重設一位，或「重設全班」（要按兩次）；只重設目前堂次，學生回到寵物畫面時生效
  - 重發序號：「發一組新序號」新增一組外型不重複的序號（舊序號保留）；新序號請記進你另存的對照表
  - 查序號：分出打錯字、沒發過、還沒領養、已領養（學生說序號輸入失敗時用）
- 看板無個人排名：只有待確認清單與序號工具會出現序號，其他都是整班數字
- 展示機模式（網址加 `?view=display`）：只顯示目前堂次與班級合作指標，大字、每 20 秒更新；連不上時顯示本機快取的上一次數字。展示機要用你的帳號登入（網址只有本人能開）
- 看板與學生端是不同專案，`LockService` 的鎖不共用（假設：兩邊寫的是不同格子或各自新增一列，衝突機率低）
